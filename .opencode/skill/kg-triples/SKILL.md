# 文本/文档 → 三元组抽取技能

按五段流水线处理用户提供的文本或文档附件。所有产出以 kg-ops 协议输出，由本地程序做 RDF 校验与原子入库，禁止直接操作数据库文件。

## 第一步：预处理与分块

1. 获取文本：用户粘贴的正文或附件（PDF/Word 等先提取纯文本，保留章节结构）
2. 清洗：去掉页眉页脚、水印、乱码、参考书目噪音
3. 识别标题层级与文体：叙事文（历史/新闻）以事件为核心；说明文/百科以实体-属性为主；表格按"行=实体、列=属性键"映射；技术文档关注概念层级
4. 分块：按语义单元（小节/段落）切为 300-800 字的块，块间保留一句重叠；逐块处理，每块独立输出一个 kg-ops 代码块

## 第二步：逐块抽取

- 全量识别候选知识元素：人名、地名、机构、概念、事件、作品、数值、时间表达
- 实体四大类判定：物理可感的存在 → 物理实体；观念/事件/作品/领域 → 抽象实体；量值作为关系端点 → 数值实体；时间作为关系端点 → 时间实体
- 建模铁律：仅作描述说明的年份、日期、数量（成立年份、测量年份、海拔、人口）一律写入所属实体的 attributes，禁止为它们单独建节点
- 属性：扁平键值对，值为字符串/数值/布尔，禁止嵌套
- 关系：识别谓词（动词/系词/介词结构），对齐主语宾语，产出（主语, 谓词, 宾语）候选

## 第三步：规范化

- 命名全称优先、统一译名；同义实体合并为一个节点，原名称收进"别名"属性
- 同名歧义靠上下文与属性区分，必要时加限定符（如"李白（诗人）"）
- 谓词使用规范词：位于/属于/发生于/参与/包含/创作/国籍/推动发展 等，同义谓词归一（"坐落于"→"位于"）
- 关系大类固定五选一：空间 / 互动 / 归属 / 时间 / 属性
- 数值单位统一换算、日期统一格式

## 第四步：融合（对齐已有图谱）

- 每块抽取前先对照提示词中的"当前图谱"摘要：已存在的实体直接用其真实 id 引用（source_id/target_id），禁止重复创建同名实体
- 本次新增的实体用 ref 占位符（如 "ref":"A"），同一块内后续关系用 source_ref/target_ref 引用
- 与已有知识矛盾的信息：创建/更新时在 attributes 中加"来源"键标注文档名与原文表述，并在说明中提示用户裁决；禁止擅自覆盖或删除已有知识
- 从文档新建的实体建议带"来源"属性记录出处文档名，保证可追溯

## 第五步：输出协议

- 先输出简短中文抽取报告：本块新建实体数、复用实体数、关系数、存疑项清单
- 每个处理块输出一个 kg-ops 代码块（一次回复可含多个代码块），格式：

````
```kg-ops
[
  {"op":"add_entity","ref":"A","name":"实体名","category":"物理实体","attributes":{"来源":"xx文档"}},
  {"op":"add_relation","source_ref":"A","target_id":3,"name":"位于","category":"空间"},
  {"op":"update_entity","id":5,"attributes":{"别名":"某某"}}
]
```
````

- 底线原则：宁可漏抽并在说明中列出存疑项，也不硬造三元组；每条知识必须能回指原文位置
